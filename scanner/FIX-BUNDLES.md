# Bundle and entry-point fixes

Baseline `scanner-preview` at `bb62a7c`, integrated November 24, 2026. The scan ledger branch was at `d01862b` when work began. [Attempt index and campaign groups](BUNDLE-ATTEMPTS.md). This report uses data from its shared ledger and the pinned CLIMB and EDGE runs.

## Verified changes

| Case | Red → green | Evidence |
| --- | --- | --- |
| Missing CFBundleExecutable on a conventional app | `archives_verify_a_same_stem_macho_when_the_app_plist_has_no_executable_key` failed with `not found: CFBundleExecutable in Info.plist`. ZIP, gzip tar and HFS now verify the same-stem Mach-O in local, remote-cli and Worker profiles. | Generated fixtures use the recorded AgentSessions 3.8.2 plist fields and synthetic headers. The earlier checksum-matched public DMG separately verified x86_64 and arm64, minimum macOS 14.0, at `AgentSessions.app/Contents/MacOS/AgentSessions`. AgentSessions is a conventional app bundle. See [BIGFOLDER.md](web/BIGFOLDER.md#agentsessions-382). |
| Same-stem script plus a separate helper | `a_same_stem_script_does_not_verify_an_undeclared_main` failed because the scan stopped before reporting the helper. It now reports the helper in the inventory and leaves the primary unverified. | The script and the Mach-O helper are both in the generated archive. |
| HFS and APFS Contents-relative executable path | `disk_images_resolve_a_contents_relative_executable_after_the_declared_lookup` failed at `Contents/MacOS/MacOS/Sci-Hub EVA`. HFS and APFS fixtures now report the corrected path, verified slices and one main inventory entry in all three profiles. | Sci-Hub EVA 6.5.1's pinned 57,761,645-byte image (SHA-256 `769aa2eff2e44b926bbde6b1611355af09cabd50e281864ea57d2d3051d8754d`) gave the same pre-fix error locally. Its inventory independently verified arm64 at `Contents/MacOS/Sci-Hub EVA`, which the fixture reproduces. |
| Universal launcher with an Intel-only runtime | The Node test previously showed an unqualified universal verdict with a two-binary inventory. The headline now scopes verified slices to the launcher. The inventory still carries both entries and reports the x86_64-only runtime. | EDGE's full Intel Android Studio inspection observed a universal primary and Intel-only Java runtime. See [EDGE.md](EDGE.md#final-native-local-checks). |
| LaTeXiT 1.15.0 32-bit Intel and PowerPC | The Node test previously offered a Rosetta verdict for i386 and PPC. The headline now identifies those verified legacy architectures. | Ledger attempts `d029319e101e7f799e889a21d786e04706461bcefdb7861b95dfc8dde7302e51` and `35d1bb3e1265478c60623b395019441ab918b5e2990da33b396bc89f3bfe9ceb` record the publisher artifact, embedded version and missing display name and minimum. The pinned download returned a TLS error on this run. Missing metadata remains unknown. [Apple 32-bit compatibility](https://support.apple.com/en-us/103076) |
| Encrypted Mach-O segment | `reads_encrypted_macho_headers_without_reading_encrypted_code` previously reported an empty encryption-command diagnostic. The scan now exposes the crypt ID, offset, and length and records per-slice encryption evidence. It verifies the synthetic arm64 header after 80 bytes. A zero ID is recorded as clear and an out-of-bounds encrypted extent is rejected. | This fixture models Apple's clear Mach-O load commands with opaque code starting at byte 4,096. An actual FairPlay download was unavailable in the supplied evidence. [Apple Mach-O definitions](https://github.com/apple-oss-distributions/xnu/blob/main/EXTERNAL_HEADERS/mach-o/loader.h) |
| ZIP wrapper with a flat inner app | `zip_wrapper_resolves_the_flat_inner_application_and_its_own_inventory` failed because the ZIP index skipped the inner plist. The scanner now reports both paths, verifies the declared inner launcher, preserves the flat plist path and includes its framework. It accepts automatic, outer-target, and inner-target scans in all three profiles. | The local directory fixture already records separate wrapper and nested-app rows. The ZIP verdict describes the observed launcher. Apple documents Mac Catalyst and iPhone or iPad apps on Mac as different deployment paths. [Apple platform guidance](https://developer.apple.com/documentation/apple-silicon/running-your-ios-apps-in-macos?changes=_1) |
| Resource-only ZIP and ZIPs with several products | The resource-only fixture previously returned missing executable. It now returns `no_executable` after a complete code inventory. A resource bundle in front of an app or installer no longer hides the verified product. Two independently verified apps return both candidate paths and require a target. | Three offline regressions cover the previously missing or arbitrary outcomes. The explicit-app path remains usable. |

Rebuild the small archives with `python3 fixtures/bundles/generate.py`. Run the tests offline from `scanner/` with `cargo test --locked -j2 -p scan-core --test formats same_stem`.
